一、你需要做的(只需一次)
=====================================================================
  打开 PowerShell 或 CMD,执行:

      gh auth login

  然后按提示回答:

      ? Where do you use GitHub?                 → GitHub.com
      ? What is your preferred protocol ...      → SSH
      ? Upload your SSH public key?              → Skip
        (你已经把公钥加到 GitHub 了,不用再上传)
      ? How would you like to authenticate?      → Login with a web browser

  接着它会显示一个一次性码(形如 1234-ABCD):
      1. 复制这个码
      2. 按 Enter → 浏览器自动打开 github.com/login/device
      3. 粘贴码 → 点 Continue → Authorize

  完成后告诉我"授权好了"。

四、整理时做了什么(以及为什么这样放)
=====================================================================
  ✅ 保留脚本平铺在根目录
     原因:install-apps-gui.ps1 与 install-desktop-apps.ps1 都用
           $PSScriptRoot 加载 app-catalog.ps1 / app-lib.ps1,
           两个 .cmd 也按相对路径调用 .ps1。
           拆到 src/ 子目录会破坏这些引用 → 保持平铺,开箱即用。

  ✅ 文档收进 docs/
     使用说明.md 与 界面预览.png 不被任何脚本引用 → 可以安全移动。

  ✅ 新增 README.md
     把「快速开始 / 文件说明 / 命令行用法 / 自定义清单 / 环境要求 /
      已知限制」集中到一页,原始完整说明归档在 docs/ 里。

  ✅ 新增 LICENSE(MIT)
     不指定默认协议的话,别人(包括未来的你换设备)用起来会有法律歧义。

  ✅ 新增 CHANGELOG.md
     作为 v1.0.0 起点,以后每次迭代往上加一节,便于回溯。

  ✅ 新增 .gitignore
     排除日志、临时目录、编辑器配置,避免误提交。

  ✅ 语法校验
     4 个 .ps1 全部通过 PowerShell 语法解析,0 错误。

  git commit -m "feat: 加了什么功能"
  git push

  建议约定(适合这类工具):
    feat:     新功能        例 feat: 支持从桌面快捷方式推断应用
    fix:      修复          例 fix: winget 输出含 ANSI 时版本解析失败
    refactor: 重构          例 refactor: 拆分 app-lib 里的路径校验
    docs:     文档          例 docs: 补充 MSIX 不支持自定义路径的说明
    chore:    杂项          例 chore: 更新 README 截图
    vX.Y.Z 版本号:
      改 app-catalog.ps1 的应用清单     → 小版本 +(1.0.0 → 1.0.1)
      改界面/新增参数/修 bug           → 次版本 +(1.0.0 → 1.1.0)
      架构性改动                       → 主版本 +(1.0.0 → 2.0.0)

  发版时:
    gh release create v1.0.0 --title "v1.0.0" --notes "首个入库版本"
