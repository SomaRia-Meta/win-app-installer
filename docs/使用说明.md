# 应用安装器（winget 图形界面版）

用 winget 批量安装 / 升级常用应用：先弹出**选择窗口**，勾选要处理的应用，可**指定安装路径**，
再点「开始执行」。执行期间有**进度条**、**实时日志**和可单独打开的**调试终端**，
出错时按原因给出**中文说明与处置建议**。

---

## 快速开始

**双击 `安装应用.cmd`**

| 区域 | 说明 |
|---|---|
| ① 选择要处理的应用 | 每行：应用 / winget 包 ID / 已装版本 / 可用版本 / 状态 / **安装位置**。支持全选·全不选·反选·重新检测；鼠标悬停可看完整路径 |
| ② 操作模式 / 安装位置 / 容错 | 安装缺失项 或 升级已安装项；可选包；演练模式；**单项超时**；**自动重试次数**；**自定义安装位置**（含"每个应用建子文件夹"、不支持时的两种策略） |
| ③ 执行与实时日志 | 进度条 + 当前项 + 已用时；winget 每行输出实时刷进深色日志区并同步打到控制台；开始执行 / 中断 / 打开调试终端 / 打开日志文件 / **以管理员身份重启** |

颜色约定：**蓝色 = 未安装**，**橙色 = 可升级**，**绿色 = 已是最新**，**灰色 = 可选包**。

## 一、指定安装路径

勾选「使用自定义安装位置」→ 填或选一个**绝对路径**（例如 `D:\Apps`）：

- 勾选「每个应用建子文件夹」（默认）：实际落地到 `D:\Apps\微信`、`D:\Apps\Steam`…
  （应用名里的 `\ / : * ? " < > |` 会被替换成 `_`）
- 不勾选：所有应用尽量装到同一个 `D:\Apps`
- 也可以只给**某个应用**固定路径：编辑 `app-catalog.ps1` 给它加 `Location='E:\Fixed\Path'`，
  优先级高于界面上的统一路径

**执行前会校验路径**（不通过就直接拦下，不会跑到一半才失败）：

| 校验项 | 不通过时的提示 |
|---|---|
| 非空、绝对路径、无非法字符 | 对应原因 |
| 盘符存在 | `盘符不存在：Z:\` |
| 能创建目录、能写入 | `无法创建目录：…` / `目录不可写（可能需要管理员权限）` |
| 剩余空间（默认要求 ≥ 2 GB） | `可用空间不足：1.2 GB（建议至少 2 GB）` |

**不是所有安装包都支持自定义位置**（winget 的 `--location` 限制）：

- MSIX / 微软商店类应用**不支持**；部分 EXE/MSI 也不支持
- 这种情况下由你选择策略：
  - **不支持时回退默认位置**（默认）：照常装上，只是落在默认位置，日志和状态列会明确写"已装(默认位置)"
  - **不支持时跳过不装**：干脆不装，状态列写"跳过(不支持自定义位置)"
- 注意区分：**位置"无效"**（路径写错）**不会**回退，直接报错——因为你明确指定了路径，
  程序不会偷偷装到别处

> winget 的 `--location` 只影响**新安装**；已装应用的升级通常保留原位置（升级时也会带上
> `--location`，但最终由安装包决定）。

## 二、异常处置（出错时会怎样）

每个应用的处理结果分四类：**成功 / 回退成功 / 跳过 / 失败（含超时、已中断）**。
失败项会按原因分类，打印**中文说明 + HRESULT + 处置建议**：

| 原因分类 | 程序行为 | 你要做的 |
|---|---|---|
| `NET_UNREACHABLE` 网络不可达（如 `0x80072EFD InternetOpenUrl() failed`） | 判定为可重试，按"自动重试"次数退避重试 | 检查网络/代理；本机实测代理会显著拖慢甚至阻断下载 |
| `NET_DNS` 域名解析失败 | 可重试 | 检查 DNS |
| `NET_TIMEOUT` 网络超时 | 可重试 | 调大"单项超时"或改善网络 |
| `NEEDS_ADMIN` 需要管理员权限（`0x80070005`） | 标记失败，汇总时提示 | 点**"以管理员身份重启"**（会走 UAC）后重试 |
| `UAC_CANCELLED` 授权被取消（`0x800704C7`） | 标记失败 | 重试并在 UAC 窗口点"是" |
| `DISK_FULL` 磁盘空间不足（`0x80070070`） | 标记失败 | 清理目标盘或改安装位置 |
| `FILE_IN_USE` 文件被占用（`0x80070020`） | 可重试；**执行前会预检正在运行的相关程序并弹窗确认** | 先关闭该应用再重试 |
| `INSTALL_IN_PROGRESS` 另一个安装在进行（`0x80070652`） | 可重试（退避等待） | 等其它安装完成 |
| `REBOOT_REQUIRED` 需要重启（退出码 3010 / `0x0BC2`） | 不算失败，提示重启后生效 | 重启 |
| `HASH_MISMATCH` 安装包哈希校验失败 | 标记失败 | `winget source reset --force` 后重试 |
| `PACKAGE_NOT_FOUND` 源里没有该包 | 标记失败 | 核对包 ID |
| `LOCATION_UNSUPPORTED` 该包不支持自定义位置 | 按②里的策略回退或跳过 | 一般无需处理 |
| `LOCATION_INVALID` 指定位置无效 | 直接失败，**不回退** | 换一个路径 |
| `MSI_FATAL` MSI 内部错误（`0x80070643`/1603） | 标记失败 | 看 `%TEMP%` 下的 MSI 日志或手动安装 |
| `UNKNOWN` 未知错误 | 标记失败，仍打印 HRESULT | 看日志详情，必要时把 HRESULT 搜一下 |
| 超时（默认 1800 秒无进展） | 杀掉 winget 进程树，标记"超时终止" | 调大"单项超时"（大安装包 + 慢网需要 3600）或改善网络 |
| 中断 | 立即结束当前项，后续不再处理 | —— |

此外：**所有执行都包在 try/catch/finally 里**，任何意外异常都会写进日志、
界面按钮会被复位（不会卡死）；日志写入失败也不会中断安装。

## 三、命令行用法

```
安装应用.cmd                                打开图形界面
安装应用.cmd -DryRun                        演练：走完整流程但不真装
安装应用.cmd -Mode install|upgrade|auto     强制模式（auto=无可装则自动转升级）
安装应用.cmd -Location D:\Apps              指定安装位置
安装应用.cmd -LocationFallbackPolicy skip   不支持自定义位置时跳过（默认 fallback 回退）
安装应用.cmd -Only 微信,QQ,夸克              只处理这几项（名称或包 ID，可逗号分隔）
安装应用.cmd -TimeoutSec 3600               单项超时改 3600 秒
安装应用.cmd -MaxRetries 2                  可重试错误自动重试 2 次
安装应用.cmd -NoGui -ScanOnly               不开窗口，只在控制台打印检测结果
```

命令行版（适合脚本/计划任务）：

```
install-desktop-apps.cmd -DryRun
install-desktop-apps.cmd -Location D:\Apps -FromDesktop
install-desktop-apps.cmd -Upgrade -Only 微信,百度网盘 -TimeoutSec 3600
install-desktop-apps.cmd -Exclude Steam,QQ
```
`-Location` 非法时会**提前以退出码 2 结束**，不会开始任何安装。

## 六、维护与注意

**增删应用**：编辑 `app-catalog.ps1`

```powershell
[pscustomobject]@{ Name='显示名'; Id='Vendor.PackageId'; Shortcut='桌面快捷方式名'; Note='备注' }
# 可选：Location='D:\Apps\固定路径'（优先于界面设置）   OptIn=$true（默认不勾选）
```
`Id` 用 `winget search <关键字>` 找到后，用 `winget search --exact --id <Id>` 确认存在。
改完先跑 `安装应用.cmd -DryRun` 演练一遍，确认清单能正常加载、路径与勾选符合预期。

**改脚本的两个硬性要求**（都实际踩过坑）：

1. `.ps1` 必须存成 **UTF-8 with BOM** —— 否则 Windows PowerShell 5.1 按 GBK 解析中文，直接语法错误。
2. **不要在 .ps1 里打全角引号** `“ ” ‘ ’` —— PowerShell 把它们当字符串定界符，会造成莫名其妙的语法错误。要引号就用 `「」`。

## 七、已知环境问题

- **GitHub 不可达时会装不上**：本机实测 `curl` 访问 GitHub 返回 HTTP 000、
  winget 报 `0x80072EFD InternetOpenUrl() failed`。托管在 GitHub 的包（VS Code、Rufus、
  Clash Verge 等）会失败；托管在国内 CDN 的（微信、百度网盘）可以，但实测只有
  **150~240 KB/s**，200MB 的包要 20 分钟以上 —— 所以默认单项超时给到 1800 秒。
  想快，先处理代理（Clash Verge / verge-mihomo 在跑时流量走代理）。
- 因为上面的原因，"装到自定义路径后文件确实落在该路径"这一环没能在真机上跑通验证；
  逻辑层面（`--location` 参数组装、不支持时的回退决策）已通过自动化用例覆盖。
  你有空时点一个小应用实测一下即可，状态列会显示实际落地路径。
